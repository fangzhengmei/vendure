# 路由前缀配置来源与可配置方案分析

## 一、AdminUiPlugin route 配置的完整传递路径

### 1.1 配置来源与服务端传递

**配置入口**：`AdminUiPlugin.init({ route: 'admin', port: 3002 })`

**传递链路**：

```
VendureConfig.plugins[]
    ↓
AdminUiPlugin.init(options: AdminUiPluginOptions)
    ├──→ static options = AdminUiPlugin.options  (静态存储)
    │
    ├──→ configure(consumer: MiddlewareConsumer)  (Nest 生命周期钩子)
    │       ├──→ consumer.apply(createProxyHandler()).forRoutes(route)
    │       │        └── Express 中间件注册路径: /admin/*
    │       │
    │       ├──→ overwriteBaseHref(indexHtmlPath, route)
    │       │        └── 写入 index.html: <base href="/admin/" />
    │       │
    │       └──→ registerPluginStartupMessage('Admin UI', route)
    │                └── 控制台日志: "Admin UI: /admin"
    │
    └──→ 前端 Angular 应用
            └── <base href="/admin/"> → Angular Router baseHref
```

**关键代码位置**：

| 操作 | 文件 | 行号 |
|------|------|------|
| 配置读取 | `packages/admin-ui-plugin/src/plugin.ts` | 184 |
| 中间件注册 | `packages/admin-ui-plugin/src/plugin.ts` | 216, 241 |
| baseHref 写入 | `packages/admin-ui-plugin/src/plugin.ts` | 366-384 |
| 启动日志 | `packages/admin-ui-plugin/src/plugin.ts` | 259 |

### 1.2 baseHref 写入实现

**文件**：`packages/admin-ui-plugin/src/plugin.ts:366-384`

```typescript
private async overwriteBaseHref(indexHtmlPath: string, baseHref: string) {
    // ... 读取 index.html
    const withCustomBaseHref = indexHtmlContent.replace(
        /<base href=".+"\s*\/>/,
        `<base href="/${baseHref}/" />`,  // 注意前后都加了 /
    );
    await fs.writeFile(indexHtmlPath, withCustomBaseHref);
}
```

结果：`<base href="/admin/" />`

## 二、DashboardPlugin route 配置的完整传递路径

### 2.1 服务端传递链路

**配置入口**：`DashboardPlugin.init({ route: 'dashboard', appDir: './dist/dashboard' })`

**传递链路**：

```
VendureConfig.plugins[]
    ↓
DashboardPlugin.init(options: DashboardPluginOptions)
    ├──→ static options = DashboardPlugin.options  (静态存储)
    │
    ├──→ configure(consumer: MiddlewareConsumer)  (Nest 生命周期钩子)
    │       ├──→ createDynamicHandler(route, appDir, viteDevServerPort)
    │       │        ├──→ createProxyHandler({ route, basePath: route })
    │       │        │        └── Vite dev server 代理: /dashboard/* → localhost:5173/*
    │       │        │
    │       │        ├──→ staticServer = express.static(dashboardPath)
    │       │        │        └── 静态文件服务: /dashboard/* → 构建产物
    │       │        │
    │       │        └──→ SPA 回退: 未匹配路径 → index.html
    │       │
    │       ├──→ consumer.apply(dynamicHandler).forRoutes(route)
    │       │        └── Express 中间件注册路径: /dashboard/*
    │       │
    │       └──→ registerPluginStartupMessage('Dashboard UI', route)
    │                └── 控制台日志: "Dashboard UI: /dashboard"
    │
    └──→ 前端 React 应用
            ├── Vite config.base (构建时, e.g. '/dashboard/')
            │       ├── import.meta.env.BASE_URL = '/dashboard/'
            │       ├── TanStack Router basepath = '/dashboard'
            │       └── vite-plugin-transform-index.ts 插入 <base href="/dashboard/">
            │
            └── 运行时: 仅通过 import.meta.env.BASE_URL 访问 (无服务端配置注入)
```

**关键代码位置**：

| 操作 | 文件 | 行号 |
|------|------|------|
| 配置读取 | `packages/dashboard/plugin/dashboard.plugin.ts` | 177 |
| 代理创建 | `packages/dashboard/plugin/dashboard.plugin.ts` | 299-304 |
| 中间件注册 | `packages/dashboard/plugin/dashboard.plugin.ts` | 181 |
| basepath 处理 (Vite) | `packages/dashboard/src/app/main.tsx` | 29-35 |
| basepath 处理 (Router) | `packages/dashboard/src/app/main.tsx` | 40 |
| basepath 处理 (NavMain) | `packages/dashboard/src/lib/components/layout/nav-main.tsx` | 101-126 |

### 2.2 关键发现：两套系统的配置是独立的

| 维度 | AdminUiPlugin route | DashboardPlugin route |
|------|---------------------|----------------------|
| 默认值 | **无默认值**，必须显式设置 | **默认 'dashboard'**（但文档建议显式设置） |
| 传递到前端 | 服务端运行时写入 index.html 的 `<base>` | 构建时 Vite `base` 配置 → import.meta.env.BASE_URL |
| 运行时访问 | Angular Router baseHref | TanStack Router basepath |
| 配置同步 | 不自动同步，两套系统独立配置 | 自身内部同步 |

**重要结论**：DashboardPlugin 的 `route` 配置**不会传递到前端运行时**。前端的 basepath 完全来自 Vite 构建时的 `base` 配置，与服务端 `DashboardPlugin.route` 无直接关联。

这意味着：
- 服务端 `route: 'my-dashboard'` + 前端 `base: '/my-dashboard/'` = ✅ 正常
- 服务端 `route: 'dashboard'` + 前端 `base: '/my-dashboard/'` = ❌ 404（Express 中间件路径与实际构建不匹配）

## 三、可配置的旧后台路由前缀方案

### 3.1 现状：硬编码 `/admin` 的问题

当前代码中**没有任何地方硬编码 `/admin`**，但跳转到旧后台的方案需要开发者手动写出 URL 前缀。例如：

```typescript
// 扩展中的菜单配置
defineDashboardExtension({
    navSections: [{
        items: [{
            id: 'legacy-products',
            title: 'Products (Legacy)',
            url: '/admin/catalog/products',  // ← /admin 前缀由开发者硬编码
            requiresPermission: ['ReadCatalog'],
        }],
    }],
});
```

当 `AdminUiPlugin.route` 不是 `'admin'` 时（例如改为 `'backend'`），这个硬编码前缀就错了。

### 3.2 设计目标

将跳转到旧后台的 URL 前缀从**硬编码**改为**可配置**，使得：

1. 开发者只需配置一次前缀（如 `'/backend'`）
2. 所有跳转链接自动使用该前缀
3. 与 `AdminUiPlugin.route` 保持一致

### 3.3 方案一：通过 virtual:vendure-ui-config 添加配置

这是最优雅的方案，符合现有配置传递方式。

#### 步骤 1：扩展 UiConfigPluginOptions

**文件**：`packages/dashboard/vite/vite-plugin-ui-config.ts`

```typescript
export interface UiConfigPluginOptions {
    api?: ApiConfig;
    i18n?: I18nConfig;
    orders?: OrdersConfig;
    /**
     * @description
     * Configuration for legacy Admin UI integration.
     * When set, enables navigation links to the legacy Angular Admin UI.
     */
    legacyAdminUi?: {
        /**
         * @description
         * The route prefix used by the AdminUiPlugin.
         * Should match the `route` option passed to AdminUiPlugin.init().
         *
         * @example 'admin'
         * @example 'backend'
         */
        route: string;
    };
}
```

#### 步骤 2：扩展 ResolvedUiConfig

```typescript
export interface ResolvedUiConfig {
    api: Required<ApiConfig>;
    i18n: Required<Omit<I18nConfig, 'defaultLocale'>> & Pick<I18nConfig, 'defaultLocale'>;
    orders: Required<OrdersConfig>;
    version: string;
    /**
     * Legacy Admin UI configuration. Undefined if not configured.
     */
    legacyAdminUi?: {
        route: string;
        baseUrl: string;  // e.g. '/admin'
    };
}
```

#### 步骤 3：在 plugin load 中处理配置

**文件**：`packages/dashboard/vite/vite-plugin-ui-config.ts:225-254`

```typescript
export function uiConfigPlugin(options: UiConfigPluginOptions = {}): Plugin {
    // ...

    async load(id) {
        if (id === resolvedVirtualModuleId) {
            if (!vendureConfig) {
                const result = await configLoaderApi.getVendureConfig();
                vendureConfig = result.vendureConfig;
            }
            const config = getUiConfig(vendureConfig, options);
            
            // 处理 legacyAdminUi 配置
            const legacyAdminUi = options.legacyAdminUi ? {
                route: options.legacyAdminUi.route,
                baseUrl: `/${options.legacyAdminUi.route.replace(/^\/|\/$/g, '')}`,
            } : undefined;
            
            return `
                export const uiConfig = ${JSON.stringify({ 
                    ...config, 
                    version: dashboardVersion,
                    legacyAdminUi,
                })}
            `;
        }
    },
}
```

#### 步骤 4：在 nav-main.tsx 中使用配置

**文件**：`packages/dashboard/src/lib/components/layout/nav-main.tsx`

```typescript
import { uiConfig } from 'virtual:vendure-ui-config';

// 外部链接检测函数
function isExternalUrl(url: string): boolean {
    if (url.startsWith('http://') || url.startsWith('https://')) {
        return true;
    }
    // 如果配置了 legacyAdminUi.route，则该前缀下的 URL 也视为外部链接
    if (uiConfig.legacyAdminUi?.baseUrl) {
        const legacyBase = uiConfig.legacyAdminUi.baseUrl;
        if (url.startsWith(legacyBase + '/') || url === legacyBase) {
            return true;
        }
    }
    return false;
}
```

#### 步骤 5：提供便利的 URL 构建函数

```typescript
// packages/dashboard/src/lib/utils/legacy-admin-url.ts
import { uiConfig } from 'virtual:vendure-ui-config';

export function getLegacyAdminUrl(path: string): string | undefined {
    if (!uiConfig.legacyAdminUi) {
        return undefined;
    }
    const baseUrl = uiConfig.legacyAdminUi.baseUrl;
    const normalizedPath = path.startsWith('/') ? path : `/${path}`;
    return `${baseUrl}${normalizedPath}`;
}

export function hasLegacyAdminUi(): boolean {
    return !!uiConfig.legacyAdminUi;
}
```

#### 步骤 6：Vite 配置示例

```typescript

export default defineConfig({

                adminApiPath: 'admin-api',
            },
            legacyAdminUi: {
                route: 'backend',  // ← 这里配置，与 AdminUiPlugin.route 一致
            },
        }),
    ],
});
```

### 3.4 方案二：通过环境变量配置

更简单的方案，通过 Vite 环境变量传递：

```bash
# .env
VITE_LEGACY_ADMIN_ROUTE=backend
```

```typescript
// packages/dashboard/src/lib/utils/legacy-admin-url.ts
const legacyRoute = import.meta.env.VITE_LEGACY_ADMIN_ROUTE;
const legacyBaseUrl = legacyRoute ? `/${legacyRoute}` : undefined;

export function getLegacyAdminUrl(path: string): string | undefined {
    if (!legacyBaseUrl) return undefined;
    const normalizedPath = path.startsWith('/') ? path : `/${path}`;
    return `${legacyBaseUrl}${normalizedPath}`;
}
```

**优点**：实现简单，无需修改 Vite 插件  
**缺点**：配置分散，与其他配置不在同一处

### 3.5 方案三：通过 defineDashboardExtension 全局注册

```typescript
// packages/dashboard/src/lib/framework/extension-api/extension-api-types.ts
export interface DashboardExtension {
    // ... existing fields ...
    
    /**
     * Configuration for legacy Admin UI integration.
     * Only one extension should define this.
     */

    };

```

```typescript

    },

```

**优点**：与扩展 API 统一  
**缺点**：配置在运行时才能生效，可能影响启动性能

### 3.6 推荐方案

**推荐方案一（virtual:vendure-ui-config）**，原因：

1. 与现有 API/i18n/orders 配置的传递方式一致
2. 构建时注入，运行时无性能损耗
3. 类型安全（TypeScript 类型定义）
4. 配置集中在 Vite 插件选项中
5. 可通过 `getConfigLoaderApi` 未来直接读取 AdminUiPlugin.route（需要服务端协作）

# 管理后台外壳与新旧路由衔接机制分析报告

## 一、概述

Vendure 正在经历从 Angular 管理后台（Admin UI）到 React 仪表板（Dashboard）的技术栈迁移。本报告深入分析业务模块如何注入新外壳、新旧路由的过渡策略、菜单与权限的合并方式，以及未迁移视图的备用机制。

---

## 二、业务模块注入外壳机制

### 2.1 核心扩展入口

新 Dashboard 采用**声明式扩展 API** 作为业务模块注入外壳的统一入口。所有扩展通过 `defineDashboardExtension()` 函数注册：

**文件位置**：`packages/dashboard/src/lib/framework/extension-api/define-dashboard-extension.ts:89-131`

```typescript
export function defineDashboardExtension(extension: DashboardExtension) {
    globalRegistry.get('registerDashboardExtensionCallbacks').add(() => {
        // 注册导航扩展（导航分区和路由）
        const navMenuModifier = registerNavigationExtensions(
            extension.navSections, 
            extension.routes
        );
        if (navMenuModifier) {
            globalRegistry.get('navMenuModifiers').push(navMenuModifier);
        }
        // 注册布局扩展（操作栏项和页面块）
        registerLayoutExtensions(extension.actionBarItems, extension.pageBlocks);
        // ... 其他扩展类型注册
    });
}
```

### 2.3 虚拟模块动态加载

通过 Vite 插件 `virtual:dashboard-extensions` 在构建时收集并执行所有扩展模块：

**文件位置**：`packages/dashboard/src/lib/framework/extension-api/use-dashboard-extensions.ts:13-27`

```typescript
export function useDashboardExtensions() {
    const [extensionsLoaded, setExtensionsLoaded] = useState(false);
    
    useEffect(() => {
        // 虚拟模块由 vite-plugin-dashboard-metadata 提供
        void runDashboardExtensions().then(() => setExtensionsLoaded(true));
        onExtensionSourceChange(() => {

        });
    }, []);

}
```

### 2.4 两阶段执行机制

扩展回调分为两个阶段执行，确保依赖关系正确：

**文件位置**：`packages/dashboard/src/lib/framework/extension-api/define-dashboard-extension.ts:26-53`

| 阶段 | 执行内容 | 说明 |
|------|----------|------|
| 阶段 1 | 注册数组形式的 `navSections`、`routes` 等 | 所有声明式扩展注册完成 |
| 阶段 2 | 应用函数形式的 `navMenuModifiers` | 可修改已注册的完整菜单配置 |

## 三、新旧路由的过渡映射

### 3.1 双路由系统并行架构

当前 Vendure 支持**两套管理后台并行运行**，用户可根据需要选择使用：

| 系统 | 技术栈 | 路由库 | 默认路径 | 状态 |
|------|--------|--------|----------|------|
| Admin UI | Angular 15+ | Angular Router | `/admin` | 成熟稳定 |
| Dashboard | React 18+ | TanStack Router | `/dashboard` | 活跃开发中 |

### 3.2 新 Dashboard 路由系统

新 Dashboard 采用**文件路由 + 动态扩展路由**的混合架构：

#### 3.2.1 文件路由（内置路由）

基于 TanStack Router 的文件系统路由，自动生成路由树：

**生成文件**：`packages/dashboard/src/app/routeTree.gen.ts`

```
├── _authenticated.tsx      # 认证布局路由（带外壳）
└── _authenticated/

    ├── _products/
    │   ├── products.tsx    # 产品列表
```

#### 3.2.3 运行时路由合并

`useExtendedRouter()` hook 在应用启动时将扩展路由合并到基础路由树中：

**文件位置**：`packages/dashboard/src/lib/framework/page/use-extended-router.tsx:12-148`

```typescript
export const useExtendedRouter = (baseRouteTree, routerOptions) => {
    const { extensionsLoaded } = useDashboardExtensions();
    
    return useMemo(() => {
        let routeTree = baseRouteTree;
        if (!extensionsLoaded) {
            return createExtendedRouter(routerOptions, routeTree);
        }
        
        // 查找认证路由作为扩展路由的父节点
        const authenticatedRouteIndex = routeTree.children.findIndex(
            r => r.id === AUTHENTICATED_ROUTE_PREFIX  // '/_authenticated'
        );
        
        // 遍历所有扩展路由并创建新路由节点
        for (const [path, config] of extensionRoutes.entries()) {
            const newRoute = createRoute({
                path: `/${pathWithoutLeadingSlash}`,
                getParentRoute: () => authenticatedRoute,
                loader: config.loader,
                component: () => config.component(newRoute),
            });
            newAuthenticatedRoutes.push(newRoute);
        }
        
        // 合并路由树
        const extendedRouteTree = routeTree.addChildren([
            ...childrenWithoutAuthenticated,
            updatedAuthenticatedRoute,
            ...newRootRoutes,
        ]);
        
        return createExtendedRouter(routerOptions, extendedRouteTree);
    }, [baseRouteTree, routerOptions, extensionsLoaded]);
};
```

### 3.3 新旧路由过渡策略

#### 3.3.1 无自动映射机制

当前实现中**没有内置的新旧路由自动映射**，原因包括：
1. 两套系统路径命名规范不同（Angular vs React 约定）
2. 新 Dashboard 正在逐步重构，页面结构不完全对齐
3. 采用渐进式迁移策略，按需迁移

#### 3.3.2 手动映射方案

插件开发者可通过扩展 API 手动注册路由映射：

```typescript
// 示例：在扩展中注册路由并关联到菜单
defineDashboardExtension({
    routes: [
        {
            path: '/my-custom-page',
            component: (route) => <MyCustomPage />,
            navMenuItem: {
                sectionId: 'catalog',  // 插入到现有菜单分区
                title: 'My Custom Page',
                requiresPermission: ['ReadProduct'],
            },
        },
    ],
});
```

```typescript
export function usePermissions() {
    const { channels } = useAuth();
    const { activeChannel } = useChannel();
    
    const hasPermissions = useCallback(
        (permissions: string[]) => {
            if (permissions.length === 0) return true;
            
            const selectedChannel = (channels ?? []).find(
                channel => channel.id === activeChannel?.id
            );
            if (!selectedChannel) return false;
            
            return permissions.some(permission =>
                selectedChannel.permissions.includes(permission)
            );
        },
        [channels, activeChannel?.id],
    );
    
    return { hasPermissions };
}
```

### 4.4 运行时菜单渲染与权限过滤

**文件位置**：`packages/dashboard/src/lib/components/layout/nav-main.tsx:94-350`

```typescript
export function NavMain({ items }) {
    const { hasPermissions } = usePermissions();
    
    // 权限过滤辅助函数
    const isItemAllowed = useCallback(
        (item: NavMenuItem) => {
            if (!item.requiresPermission) return true;
            const permissions = Array.isArray(item.requiresPermission)
                ? item.requiresPermission
                : [item.requiresPermission];
            return hasPermissions(permissions);
        },
        [hasPermissions],
    );
    
    // 按分区过滤并排序
    const getSortedSections = useCallback(
        (placement: NavMenuSectionPlacement) => {
            return items
                .filter(item => item.placement === placement)
                .sort(sortByOrder)
                .map(section => {
                    if ('items' in section) {
                        // 过滤子菜单项权限
                        const allowedItems = (section.items ?? [])
                            .filter(isItemAllowed)
                            .sort(sortByOrder);
                        return { ...section, items: allowedItems };
                    }
                    return section;
                })
                .filter(section => {
                    // 移除权限过滤后为空的分区
                    if ('items' in section) {
                        return section.items && section.items.length > 0;
                    }
                    return isItemAllowed(section as NavMenuItem);
                });
        },
        [items, isItemAllowed],
    );
    
    const topSections = useMemo(() => getSortedSections('top'), [getSortedSections]);
    const bottomSections = useMemo(() => getSortedSections('bottom'), [getSortedSections]);
    
    // 渲染顶部和底部分区
    return (
        <>
            <SidebarGroup>
                <SidebarMenu>
                    {topSections.map(item => renderSection(item, ...))}
                </SidebarMenu>
            </SidebarGroup>
            {bottomSections.length ? (
                <SidebarGroup className="mt-auto">
                    <SidebarGroupLabel>Administration</SidebarGroupLabel>
                    <SidebarMenu>
                        {bottomSections.map(item => renderSection(item, ...))}
                    </SidebarMenu>
                </SidebarGroup>
            ) : null}
        </>
    );
}
```

### 4.5 工具栏项合并机制

**文件位置**：`packages/dashboard/src/lib/components/layout/app-layout.tsx:32-77`

```typescript
function mergeToolbarItems(builtinItems, extensionItems): MergedToolbarItem[] {
    const result: MergedToolbarItem[] = [];
    
    // 首先添加没有定位的扩展项（置于最前）
    const unpositionedExtensions = extensionItems.filter(ext => !ext.position);
    for (const ext of unpositionedExtensions) {
        result.push({ type: 'extension', item: ext });
    }
    
    // 处理每个内置项，按 before → replace → after 顺序合并扩展项
    for (const builtinItem of builtinItems) {
        const matchingExtensions = extensionItems.filter(
            ext => ext.position?.itemId === builtinItem.id
        );
        
        const orderPriority = { before: 1, replace: 2, after: 3 };
        const sortedExtensions = [...matchingExtensions].sort(
            (a, b) => orderPriority[a.position!.order] - orderPriority[b.position!.order]
        );
        
        // 处理替换逻辑
        const hasReplacement = sortedExtensions.some(ext => ext.position?.order === 'replace');
        
        // 插入到合适位置
        let builtinInserted = false;
        for (const ext of sortedExtensions) {
            if (!builtinInserted && !hasReplacement && ext.position?.order !== 'before') {
                result.push({ type: 'builtin', item: builtinItem });
                builtinInserted = true;
            }
            result.push({ type: 'extension', item: ext });
        }
        
        if (!builtinInserted && !hasReplacement) {
            result.push({ type: 'builtin', item: builtinItem });
        }
    }
    
    return result;
}
```

## 五、未迁移视图的备用策略

### 5.1 三级降级服务策略

DashboardPlugin 实现了智能的三级降级服务，确保在各种环境下都能正常访问：

**文件位置**：`packages/dashboard/plugin/dashboard.plugin.ts:287-395`

| 优先级 | 模式 | 触发条件 | 说明 |
|--------|------|----------|------|
| 1 | Vite 开发服务器 | 检测到端口 5173 有服务运行 | 支持 HMR 热更新，开发体验最佳 |
| 2 | 构建静态文件 | `appDir` 目录存在 `index.html` | 生产环境默认模式 |
| 3 | 默认引导页面 | 以上都不可用 | 显示"开始使用"引导页面 |

#### 5.1.1 Vite 开发服务器代理

```typescript
private createDynamicHandler(route: string, appDir: string, viteDevServerPort: number) {
    const dynamicRouter = express.Router();
    
    dynamicRouter.use(async (req, res, next) => {
        // 检查 Vite 开发服务器（最高优先级）
        const isViteRunning = await this.checkViteDevServer(viteDevServerPort);
        const hasBuiltFiles = this.checkBuiltFiles(appDir);
        
        const newMode: 'vite' | 'built' | 'default' = isViteRunning 
            ? 'vite' 
            : hasBuiltFiles ? 'built' : 'default';
        
        // 路由到对应处理器
        if (isViteRunning) {
            return proxyHandler(req, res, next);
        }
        if (hasBuiltFiles) {
            return staticServer(req, res, next);
        }
        return defaultPage(req, res, next);
    });
    
    return dynamicRouter;
}
```

#### 5.1.2 静态文件服务

```typescript
private createStaticServer(dashboardPath: string) {
    const dashboardServer = express.Router();
    
    // 资源文件设置长缓存（content-hash 命名，不可变）
    dashboardServer.use(
        '/assets',
        express.static(path.join(dashboardPath, 'assets'), {
            maxAge: '1y',
            immutable: true,
        }),
    );
    dashboardServer.use('/assets', (_req, res) => res.status(404).end());
    
    // 其他静态文件
    dashboardServer.use(express.static(dashboardPath));
    
    // SPA 回退：所有未匹配路径返回 index.html
    dashboardServer.use((req, res) => {
        res.sendFile('index.html', { root: dashboardPath });
    });
    
    return dashboardServer;
}
```

## 七、迁移建议

### 7.1 渐进式迁移步骤

1. **并行运行**：同时启用 AdminUiPlugin 和 DashboardPlugin
2. **菜单跳转**：在新 Dashboard 菜单中添加旧管理后台链接
3. **模块迁移**：按业务优先级逐个迁移模块到新 Dashboard
4. **路由重定向**：迁移完成后，在旧管理后台添加重定向到新 Dashboard
5. **逐步下线**：确认所有功能迁移完成后，移除旧 Admin UI

### 7.2 扩展开发最佳实践

1. 使用 `defineDashboardExtension()` 统一注册所有扩展
2. 优先使用数组形式的 `navSections` 添加新分区
3. 需要修改现有菜单时使用函数形式的修改器
4. 始终为菜单项设置正确的 `requiresPermission`
5. 使用 `PermissionGuard` 组件保护敏感 UI 元素
